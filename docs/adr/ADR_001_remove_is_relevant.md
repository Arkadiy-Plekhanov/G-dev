# ADR-001: удаление is_relevant из quality_expressions

**Статус:** принято, реализовано.
**Дата:** 22 августа 2026.
**Решение владельца:** «Однозначно, что запись = релевантность, но в таком случае релевантность вообще не имеет того значения, чтобы её указывать. Можно облегчить архитектуру без релевантности.»

## Контекст

`quality_expressions` изначально унаследовала из forensic-аудита исходного Excel-файла две колонки: `is_relevant boolean` и `score smallint NULL`, с CHECK-инвариантом «релевантно ⇔ есть оценка». В Excel это было осмысленно: пользователь просматривал список кандидатов-качеств и для каждого явно отмечал «релевантно» или «не релевантно», иногда без оценки.

Актуальный UX продукта (mockups + решение владельца из более раннего разговора) устроен иначе: качество **сначала явно выбирается** («проявилось в этом действии»), и только затем оценивается 0–4. Пути «отметить как нерелевантное без оценки» в текущем UX не существует — невыбранное качество просто не создаёт записи. При таком дизайне `is_relevant` стало полем, которое физически не может принимать значение `false` через штатный UI: колонка осталась только как наследие другой, более ранней модели взаимодействия.

## Решение

Убрать `is_relevant` из `quality_expressions`. `score` становится `NOT NULL` (0–4 всегда обязателен). Существование строки `quality_expressions` **само по себе** и есть релевантность — отдельного поля для этого не требуется.

## Затронуто

- Схема: `quality_expressions.is_relevant` удалена; `score` → `NOT NULL`; CHECK-инвариант релевантность↔оценка удалён (стал бессмысленным — заменяется просто `CHECK (score BETWEEN 0 AND 4)`, который уже был).
- VIEW: `quality_stats`, `action_stats`, `v_data_quality_alerts` — убраны все `WHERE .../FILTER (WHERE is_relevant)`, поскольку фильтровать больше не по чему (все строки релевантны по построению).
- API: `ExpressionIn`/`ExpressionOut`/`ExpressionNestedIn` — `is_relevant` убран, `score` обязателен.
- Тесты: `test_security_gate.py` (фикстура), `test_atomic_action.py` (тест на инвариант релевантность↔оценка заменён тестом на просто обязательность оценки).
- Миграция: `09_remove_is_relevant.sql` — если в БД существуют строки `is_relevant=false` (в реальных данных владельца таких строк нет ни одной, проверено), они **удаляются** при миграции, поскольку у них нет корректного представления в новой модели (оценки нет, а значит и не может быть валидной строки).

## НЕ затронуто

Семантика самой шкалы 0–4 (0 = «качество проявилось в обратную сторону/провал», не «не участвовало») — не меняется, это отдельное, уже подтверждённое ранее решение. Модель целей, композиция фокуса, идеалы, статистика по окнам 30 дней — не затронуты.
